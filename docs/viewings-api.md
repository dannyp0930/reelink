# 관람 기록 조회 API

기준일: 2026-09-15. C3에서 구현한 조회 계약이다. 브라우저는 같은 출처의 `/api/viewings`로 요청하고 Backend는 `/viewings`를 처리한다.

## 목록 조회

`GET /viewings`는 로그인한 사용자의 관람 회차를 조회한다. 같은 영화의 재관람도 각각 반환한다. 관리자도 다른 사용자의 기록을 조회할 수 없다.

| query | 기본값 | 허용값·동작 |
| --- | --- | --- |
| `month` | 전체 기간 | `0001-01`~`9999-12`의 `YYYY-MM`. 관람일 기준 해당 월만 조회 |
| `rating` | `all` | `all`, `unrated`, `0`~`5`의 0.5점 단위. 정수의 `.0` 표기도 허용 |
| `sort` | `newest` | `newest`, `rating`, `oldest` |
| `page` | `1` | 1~1,000,000의 정수 |
| `limit` | `50` | 1~100의 정수 |

조건은 함께 적용한다. 예를 들어 `/api/viewings?month=2024-02&rating=4.5&sort=newest&page=1&limit=20`은 2024년 2월의 4.5점 기록을 최근 관람일부터 20건씩 조회한다. `rating=0`은 0점만, `rating=unrated`는 미평가만 조회한다.

빈 값, 공백, 반복 query, 지원하지 않는 필드·정렬, 잘못된 월·평점·페이지는 `400`이다. `page`·`limit`은 선행 0, 소수, 지수 표기를 허용하지 않는다. `userId`도 허용하지 않으며 소유자는 항상 세션에서 결정한다. 비로그인은 `401`이다.

## 정렬

- `newest`: 관람일 내림차순 → id 내림차순.
- `rating`: 평점 내림차순, 미평가 마지막 → 관람일 내림차순 → id 내림차순.
- `oldest`: 관람일 오름차순 → 시각 오름차순, 미입력 마지막 → id 오름차순. 캘린더의 날짜별 기록 순서로 사용한다.

시각 미입력은 `null`이고 자정은 `00:00`이다. 관람일은 시간대 변환 없이 기록한 날짜를 유지한다. 월 범위는 해당 월 1일 이상, 다음 달 1일 미만으로 계산한다.

## 응답과 페이지

기존 배열 응답을 다음 객체로 바꿨다. 임시 Frontend의 초기 조회·새로고침과 관련 테스트도 `items`를 읽도록 변경했다.

```json
{
  "items": [],
  "page": 1,
  "limit": 50,
  "totalItems": 0,
  "totalPages": 0
}
```

`items`의 각 항목은 기존 관람 상세 응답과 같다. 관람 일시·유형·상세·평점과 필요한 영화·극장 정보를 포함한다. 평점 응답은 `ratingHalfStars` 0~10 또는 `null`이며 표시 점수는 2로 나눈다. `watchedOn`은 기존 UTC 자정 ISO 형식을 유지하므로 화면도 UTC 날짜 기준으로 표시한다. 조회할 때 TMDB를 추가 호출하지 않는다.

`totalItems`는 필터를 적용한 전체 건수, `totalPages`는 `ceil(totalItems / limit)`다. 기록이 없으면 페이지 수는 0이다. 마지막 페이지를 넘겨도 `200`과 빈 `items`를 반환하며 요청한 `page`와 전체 건수는 유지한다. 한 응답 안의 건수와 기록은 `RepeatableRead` 트랜잭션으로 같은 시점의 데이터를 읽는다. 응답은 기존 `Cache-Control: no-store`를 유지한다.

캘린더에서는 `month`·`rating`·`sort=oldest`를 고정해 마지막 페이지까지 조회한다. 도중에 요청이 실패하면 완성된 월로 표시하지 않는다. 페이지 요청 사이에 기록이 추가·수정·삭제되면 순서와 건수가 달라질 수 있다. 화면에서 변경한 뒤에는 월 전체를 다시 조회한다. 여러 요청에 걸친 고정 스냅샷은 제공하지 않는다.

## 상세·쓰기와 후속 작업

`GET /viewings/:id`와 POST·PATCH·DELETE 계약은 유지한다. 타인 기록과 없는 기록의 상세·수정·삭제는 `404`다. 쓰기 입력은 [도메인 필드](domain-fields.md), 영화 정보는 [영화 API](movies-api.md)를 참고한다.

C3는 조회 API와 기존 화면의 응답 연결까지 완료했다. 현재 임시 화면은 여전히 최근 50건을 표시한다. 필터·정렬·페이지 조작 화면, 상세·수정 route는 D, 캘린더와 공통 평점 필터는 E에서 연결한다. 새 의존성·DB migration·극장 데이터 적재는 추가하지 않았다.
