# 극장 검색과 초기 등록

`GET /api/cinemas?q=용산`은 로그인한 사용자의 내부 극장 검색이다. Backend 직접 경로는 `/cinemas`다.

- `q`는 선택값이다. 앞뒤 공백을 제거한 최대 100자이며 배열·제어 문자는 거부한다. 생략하거나 비우면 이름순 첫 50건을 반환한다.
- 이름 부분 일치로 검색하며 영문 대소문자를 구분하지 않는다. `%`, `_`, `\`는 검색 문자 그대로 처리한다.
- 응답은 `id`, `name`, `chain`, `status`, `address`를 가진 배열이다. 이름·ID 오름차순으로 최대 50건이며 결과가 없으면 `[]`이다. 주소는 없으면 `null`이다.
- 과거 관람을 기록할 수 있도록 휴업·폐업 극장도 포함한다. 관람 생성·수정·목록·상세 응답의 `cinema`에도 같은 필드를 제공하고 미지정이면 `null`이다.
- 화면에서 검색어를 바꾸면 400ms 후 조회한다. 이전 요청은 취소하고 늦은 응답은 무시한다. 선택한 극장은 검색 실패나 다른 검색 결과가 와도 유지되며 미지정을 선택하면 해제된다. 검색 입력의 Enter는 관람을 저장하지 않는다.

## 초기 데이터 등록 절차

2026-09-14 개발 DB의 극장은 0건이다. 지도 API·전국 선적재는 도입하지 않았으며 자주 쓰는 지점부터 공식 지점 페이지에서 이름·주소·운영 상태를 확인해 등록한다.

1. Backend의 `DATABASE_URL`이 등록할 로컬 개발 DB인지 확인한다. 아래 명령으로 Prisma Studio를 연다.
2. `Cinema`에 `name`, `chain`, `status`, 필요하면 `address`를 입력한다. `chain`은 `CGV`, `LOTTE`, `MEGABOX`, `CINE_Q`, `INDEPENDENT`, `OTHER` 중 하나이며 `status`는 `ACTIVE`, `TEMPORARILY_CLOSED`, `CLOSED` 중 하나다. ID·생성 시각은 기본값을 사용한다.
3. 같은 체인·이름이 있으면 새 행을 만들지 않고 기존 행을 수정한다. 과거 기록에서 사용하는 지점은 삭제 대신 상태를 변경한다.
4. 앱의 극장 검색에서 등록한 지점명·주소·상태를 확인한다. Studio는 사용 후 종료한다.

```powershell
pnpm --dir backend exec prisma studio --port 5556
```

CLI 도움말로 명령 옵션을 확인했다. 이번 작업에서 Studio로 실제 극장을 등록하지는 않았다. 로컬 극장 데이터는 Git으로 동기화되지 않으므로 다른 PC에는 별도 등록하거나 DB 백업·복원으로 옮긴다.

## 검증

`pnpm --dir backend test:e2e viewings`에서 로그인 필수, 이름 검색, 공백·대소문자·특수문자, 50건 상한, 빈 결과, 휴폐업과 관람 응답을 확인한다. 테스트 데이터는 `reelink_test`에만 만들고 종료 시 정리한다. `scripts/check-movie-metadata.cjs`는 데스크톱·모바일에서 검색·선택 유지·실패 재시도·저장값을 검증한다.
